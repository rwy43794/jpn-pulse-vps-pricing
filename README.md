## 为什么日本服务器的选择难点在线路

因为东京到上海的直线距离不到 1700 公里，物理延迟上限摆在那儿，各家用的硬件也拉不开代差，真正分出高下的是回程走哪条线。

便宜日本 VPS 常见的问题就在回程。普通 BGP 或 NTT 转接的机器，白天测速能跑满，晚上八点一过开始丢包，做站的人对这个应该不陌生。GoMami 官方的说法是每个节点与多家国际及国内运营商互联，电信走 CN2、联通走 AS9929、移动走 CMI，按源 IP 自动选回程，多上游冗余并支持自动故障切换。

这套线路配置在日本节点上是默认给的，不需要额外付费加购。付费加购的是 600 Gbps 高防清洗，而这一点官网首页和文档有落差：首页把“up to 600 Gbps mitigation”写得很像标配，文档里明确默认只有 best-effort 基础清洗。

还有一件事要说清楚：GoMami 的日本产品线只有 JPN Pulse 一条，没有 Turin，也没有 Forge。Turin 是香港独占的性能旗舰，Forge 是香港的独立服务器系列。在 GoMami 自己的节点选择建议里，目标华北用户推日本或香港（联通路由优化好），目标全中国的用户直接推香港。日本在这个体系里的定位，是给北方联通用户和需要日本落地的业务准备的备选节点。

先 traceroute，别先跑分。从国内的测试点往东京机器做一次回程追踪，回程应该从 CN2（AS4809）、9929 或 CMIN2 进入国内，对应你的宽带运营商。如果看到 AS4837 或者普通的 NTT 转接，说明线路没落对，直接开工单。

这是判断这台机器值不值这个价最快的办法，比看任何测评都直接。

**默认 DDoS 防护是 best-effort。** 大流量攻击影响到同网段其他客户时，系统会对你的 IP 执行黑洞，持续 30–60 分钟，自动解除，无法人工干预。这期间出入流量全部丢弃。600 Gbps 的专业清洗是付费加购，需要联系客服。

**工单是按优先级排队的。** 官方给出的响应时限是：服务器完全不可用（紧急）< 2 小时，服务受影响但部分可用（高）< 6 小时，一般技术问题（中）< 12 小时，咨询建议（低）< 24 小时。也就是说，如果只是“想问一下”的问题，最好别指望当天有回音；真出故障时按紧急分类提交，才拿得到两小时内的响应。分错类会白等。
